## Hard-won bugs / discoveries

These should NOT need to be re-learned in a future session. Saved to memory `yahoo_gotchas.md` too:

1. **Yahoo returns HTTP 999 if no `User-Agent` header.** Hit this on `/draftresults`. Added `User-Agent: fantasy-copilot/1.0` to every connector request via sed.

2. **NBA stat_id 2 = MIN, not 8.** I assumed 8 because the dict had `'8': 0.875`. That was FT%. Real minutes is stat_id 2.

3. **`Infinity` in Yahoo rate-stat responses** (FT% on 0/0). `float("Infinity") → inf`, and JSONB rejects on insert. `_stats_to_box` filters NaN/Inf before writing.

4. **Transactions endpoint is incomplete.** `/league/{key}/transactions` only covers post-draft moves. Drafted-and-never-traded players show zero history. Must also pull `/league/{key}/draftresults` and seed an "add" event per pick at the league's `draft_time`.

5. **`movement_type: "trade"` is real.** My initial sync filtered to `{add, drop}`. That dropped EVERY trade. Bam Adebayo had 5 trade transactions → zero events recorded. Fix: accept `add | drop | trade`.

6. **Per-date stats need date in path, not query.** `;date=YYYY-MM-DD` as a path segment after `stats;type=date`.

7. **Yahoo access tokens last 1 hour.** Call `get_fresh_access_token(db, user)` before any sustained fan-out — refresh happens automatically + rotates the refresh token.

8. **Schedule was forward-only.** Past-date opponent lookups failed silently because `nba_schedule` had no rows for past regular season. Added `backfill_schedule(start, end)` — ran once, idempotent. The `relink-existing-game-logs` one-off filled 243 stale rows.

9. **Tipoff bot detection.** Yahoo also rate-limits if you fan out too aggressively. `_MAX_CONCURRENT_FETCHES = 6` semaphore in `player_history.py` keeps things friendly.

## Architecture decisions made

1. **Per-date stats cache lives in `nba_game_logs`** (existing table). Off-day placeholders written as `box: {"_no_game": 1}` so subsequent loads of the same range are zero round-trips.

2. **`player_ownership_events` is one row per change**, not a snapshot of current state. Walking events oldest→newest gives intervals. Built `_build_intervals()` in the route as derived data.

3. **No agent involvement on per-date stats or projection.** Pure functions, pure DB reads, league-scoped valuator computes fps. Cheap and fast. Agent stays in chat tab.

4. **Compare reuses `/api/players/{league_id}/{player_id}` N times** via `useQueries` — no new backend endpoint, side-by-side rendering happens client-side.

5. **Team colors via `team_id % 12-palette`** — stable across every player's timeline in the league. Free agency = neutral grey. User's team gets an orange ring.

6. **Admin gate is user-id based** (`ADMIN_USER_IDS=1,2,...` env), not email-based, because Yahoo doesn't expose user email cleanly. Captured in BACKLOG for public launch — switch to email when we have email collection.

## Mobile setup (NEW today)

User got the Mac authenticated for Claude Code Remote Control:

```bash
# Mac, current shell needs to be free of API-key auth:
unset ANTHROPIC_API_KEY   # or remove from ~/.zshrc
unset CLAUDE_CODE_OAUTH_TOKEN  # if set
claude         # then /login → "Sign in with claude.ai"
# Then:
claude remote-control --spawn=worktree --name "Fantasy Copilot"
```

That prints a session URL + QR. Scan with the Claude iOS app → tap **Code** tab → all sessions land in `.claude/worktrees/` automatically. Agent runs on Mac, phone is a thin client.
